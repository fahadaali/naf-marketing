# منصة ناف للتسويق — NAF Law Marketing Management Platform

منصة ويب داخلية لإدارة الأعمال التسويقية لشركة ناف للاستشارات القانونية (الرياض): إنشاء المحتوى وتوليده، الحملات، الجدولة والنشر، التحليلات، ونظام أدوار وموافقات تسلسلي — بواجهة عربية RTL بالكامل على بنية Cloudflare.

## البنية التقنية

| الطبقة | التقنية |
|---|---|
| الواجهة | React + Vite (عربي RTL) — تُخدَم كأصول ثابتة من الـ Worker |
| الخادم/API | Cloudflare Workers + Hono |
| قاعدة البيانات | Cloudflare D1 (SQLite) |
| تخزين الوسائط | Cloudflare R2 |
| المصادقة | الدخول الموحّد عبر `naf-id` (حزمة `naf-auth`) — الجلسة في KV |
| المهام المجدولة | Cloudflare Cron Triggers |
| المفاتيح السرية | Cloudflare Secrets (Claude، مزوّد النشر، سرّ الدخول الموحّد) — لا تصل المتصفح |

## المزايا

- **إنشاء المحتوى** من ثلاثة مصادر: يدوي، توليد بالذكاء الاصطناعي (Claude)، وتحويل خبر RSS إلى مسودة.
- **محرر نصوص غني** عربي RTL يوحّد المصادر الثلاثة، مع نسخ مخصّصة لكل منصة (variants).
- **دورة اعتماد تسلسلية**: مسودة ← مراجعة التسويق ← اعتماد المدير العام ← مجدول ← منشور، مع سجل موافقات كامل وإمكانية الرفض بسبب إلزامي.
- **الحملات** وحدةَ عملٍ وقياس: صفحةٌ لكل حملة بمسارها، وشريطُ أداءٍ يقيس
  الظهور والتفاعل والوصول أمام مستهدفاتٍ مسجّلة، ولوحةُ محتوى بحالاته
  الثماني بالسحب، وخطٌّ زمنيّ يقول ما نُشر وما تأخّر وكم يوماً مرّ بلا نشر.
  والقائمة تُبحث وتُصفّى وتُفرز، بعرضين: جدول ولوحة كانبان.
  ولا حذف للحملات — أرشفةٌ تُخرجها من القائمة وتُبقي محتواها وأرقامها.
- **الجدولة والنشر التلقائي** عبر Cron بتوقيت الرياض (AST)، ومهام idempotent لا تُكرّر النشر.
- **طبقة نشر مجرّدة** محايدة للمزوّد (Mock/Buffer/SocialAPI.ai/Ayrshare) خلف واجهة `PublishingProvider`.
- **سجلّ مؤشرات كامل** يطبّق «دليل مؤشرات التسويق والتحليل»: مئةٌ واثنان وعشرون مؤشراً في عشر طبقات، كلٌّ بفئته ووحدته ودوريته ومستهدفه ومعياره القطاعي وقراره المحتمل، واثنان وستون منها تُحتسب آلياً.
- **شاشة تحليلات على طبقات الدليل** تصدّرها اللوحة المختصرة — عشرة أرقام تُراجَع أسبوعياً — ومعها دليل المؤشرات وتسجيل القيم والمستهدفات.
- **مصادر خارجية مربوطة**: منصة إدارة الشركة (العملاء المحتملون ومسار البيع)، وتحليلات الموقع، وأدوات مشرفي المواقع، والملف التجاري، وأربعةٌ أخرى بعقدٍ موحّد.
- **أدوار وصلاحيات** مخزّنة في قاعدة البيانات، يعدّلها المدير العام من الواجهة ويسري الأثر فوراً.

## الإعداد المحلي (macOS)

المتطلبات: Node.js 18+، حساب Cloudflare، Wrangler.

```bash
# 1) تثبيت الاعتماديات
npm install
npm --prefix web install

# 2) إنشاء موارد Cloudflare
npx wrangler d1 create naf_marketing        # انسخ database_id إلى wrangler.toml
npx wrangler r2 bucket create naf-marketing-media

# 3) تطبيق مخطط قاعدة البيانات محلياً
npm run db:migrate:local

# 4) المفاتيح السرية للتطوير
cp .dev.vars.example .dev.vars               # ثم عدّل القيم

# 5) التشغيل (الواجهة + الـ API معاً)
npm run dev
# الواجهة: http://localhost:5173  |  الـ API: http://localhost:8787
```

**لا تهيئة أولى ولا إنشاء حساب من المنصة.** المصادقة كلُّها في المركز:
أوّل داخلٍ من `naf-id` يُنشأ سجلّه هنا بالدور الافتراضي `writer`، ثم
يُرفَع مسؤولاً من القاعدة مرّةً واحدة:

```sql
UPDATE users SET role_name = 'general_manager' WHERE email = '…';
```

وما بعدها يُدار من **الإعدادات ← المستخدمون**. وشاشةُ الدخول بكلمة مرور
و`‎/setup` أُغلقتا في الخادم — السبب في `src/routes/auth.ts`.

## النشر على الإنتاج

```bash
# المفاتيح السرية عبر Secrets (لا تُخزَّن في الكود إطلاقاً)
npx wrangler secret put <NAME>

# بناء الواجهة، ثم تطبيق الهجرات، ثم نشر الـ Worker
# (يخدم الواجهة والـ API والـ Cron)
npm run deploy
```

**وقائمة الأسرار في [`.dev.vars.example`](.dev.vars.example) وحدها**، بشرح
كلٍّ منها وما يتعطّل بغيابه. وكانت مسرودةً هنا كذلك ثلاثةً من أربعةٍ
وعشرين — ينقصها `AUTH_CLIENT_SECRET` الذي بدونه لا دخول أصلاً — فمن نشر
متّبعاً هذا الملف وحده وجد بابه مغلقاً بلا سبب ظاهر. ويحرس تطابقَ القائمة
مع ما يقرؤه الكود `test/envContract.test.ts`.

**الهجرات داخل `npm run deploy` لا قبله بأمرٍ مستقلّ.** كانت خطوةً منفصلة
يُذكِّر بها هذا الملف، فينفّذها من يقرأه وينساها من لا يقرأه — وينساها
المسار الآلي دائماً. وترتيبها ملزم: عاملٌ جديد يقرأ عموداً لم يُنشأ بعد
يردّ ٥٠٠ على أول طلب، ونافذةُ الخطأ تُقاس بالدقائق لا بالثواني.
والأمر لا يُطبّق إلا ما لم يُطبَّق (جدول `d1_migrations`)، فتكراره في كل
نشرة لا يفعل شيئاً.

الربط بـ GitHub: عند ربط المستودع بـ Cloudflare، كل `push` إلى الفرع
الرئيسي ينشر تلقائياً — وأمرُ البناء هناك `npm run deploy`، فالهجرات
تمرّ معه بأوراق اعتماد كلاودفلير نفسها. لا سرَّ في GitHub يحتاجه هذا
المسار.

و`.github/workflows/deploy.yml` مسارٌ احتياطيّ يدويّ لحين تعطّل ذلك،
وهو وحده ما يحتاج `CLOUDFLARE_API_TOKEN` و`CLOUDFLARE_ACCOUNT_ID` في
أسرار المستودع.

## المهام المجدولة (Cron)

**مشغّل واحد لا ثلاثة**: `*/2 * * * *` في `wrangler.toml` — حساب
كلاودفلير محدود بخمس مهام إجمالاً — والتوقيت يُدار داخل `src/cron.ts`.

| المتى | المهمة |
|---|---|
| كل دورة (دقيقتان) | نشر المواعيد المستحقّة · دفعةُ نشرةٍ بريدية · مزامنة تعليقات بطاقات بيسكامب |
| بداية كل ساعة | جلب RSS · سحب لقطات التحليلات · تعليقات المنصات · تحليلات النشرة · تنبيهات التأخر |
| ٠١:٠٠ UTC (٠٤:٠٠ الرياض) | سحب مصادر المؤشرات واحتساب الآلية منها — للفترة الجارية والسابقة، وللأنواع الثلاثة |
| السبت ١٨:٠٠ UTC | التقرير الأسبوعي يُرفع إلى بيسكامب |
| أول الشهر ١٨:٠٠ UTC | التقرير الشهري يُرفع إلى بيسكامب |

والنشر لم يعد تلقائياً: يتمّ يدوياً بـ«نشر الآن»، ومن يفوت موعده يظهر «متأخر».

## بنية المشروع

```
src/                 # خادم Workers (Hono)
  routes/            # نقاط API — تحت /api عدا publicPages و emailTracking:
                     #   auth · users · permissions · settings · posts · campaigns
                     #   schedules · media · rss · analytics · metrics · integrations
                     #   basecamp · comments · notifications · templates · search · audit
                     #   buffer · socialapi · webhooks · newsletters · subscribers
                     #   siteApi (/api/public) · siteMedia (/api/public-media)
                     #   publicPages (/articles) · emailTracking (/e)
  services/          # claude · rss · publish · analytics · metrics · crmSync · workflow
                     # newsletter* · email · pdf/docx/xlsx · basecamp* · notify · alerts
  adapters/          # طبقة النشر المجرّدة (mock · buffer · socialapi · ayrshare)
                     # ومصادر المؤشرات (sources) وإدارة الشركة (crm)
  cron.ts            # معالج المهام المجدولة
migrations/          # مخطط D1 + بذور الصلاحيات والإعدادات
web/                 # واجهة React (Vite) — عربي RTL
```

## الأمان

- كل المفاتيح عبر Cloudflare Secrets فقط، ولا تصل الواجهة إطلاقاً؛ كل نداءات Claude/المزوّد تمر عبر Workers.
- التحقق من الصلاحيات على الخادم لكل عملية حساسة (لا يُعتمد على إخفاء الأزرار).
- لا كلمات مرور محلية أصلاً: لا مسار دخولٍ إلا المركز، وعمر الرمز خمس عشرة دقيقة كي يسري الإيقاف المركزي خلال ربع ساعة.
- الأسرار التي تُخزَّن في جدول `settings` تحمل البادئة `secret:` — لا تخرج من `GET /api/settings` ولا تُقبل في `PUT`.
- الإعدادات ترفض تخزين أي مفتاح سري.

## ملاحظات

- **لا تكتب قيمة لون في أي ملف.** الرموز كلُّها في `web/src/naf-theme.css` المنقول من سجلّ ناف، و`styles.css` لا يحمل قيمة لون واحدة. والاستثناءات أربع لا خامس لها — قوالب البريد، وألوان العلامات الخارجية، والطباعة وPDF، ووسم `theme-color` — وكلُّها موثّقة في موضعها. التفصيل في `CLAUDE.md` §١.
- مزوّد النشر الافتراضي `mock` لتجربة كل التدفّق دون تكلفة؛ بدّله من **الإعدادات ← المنصات والمزوّد** عند تفعيل مزوّد حقيقي. والمدعوم أربعةٌ لا غير — `mock` و`buffer` و`socialapi` و`ayrshare` — وما عداها يردّ «مزوّد غير مدعوم» عند أول نشر ولا يسقط صامتاً إلى التجريبي.
